> Актуально на 14 ноября 2026 года. Документ описывает требования кейса, содержимое рабочей папки, текущее состояние реализации и ближайшие шаги. Обновляй его по мере изменения решений и структуры проекта.

## 1. Краткое описание

«Решись Авиа» — учебный проект о динамическом ценообразовании и прогнозировании спроса на авиабилеты. Текущая рабочая папка относится к третьему блоку кейса — «Разработка». Задача этого блока — превратить результаты прогноза спроса в удобный инструмент для сотрудника авиакомпании: пользователь задаёт маршрут, дату и цену, а приложение показывает доступную вместимость самолёта и ожидаемые продажи.

Главная цель интерфейса — дать менеджеру понятный ответ на практический вопрос: сколько пассажиров, вероятно, захотят купить билет по выбранной цене, сколько из них сможет перевезти самолёт и насколько рискован прогноз.

В папке есть основная адаптивная страница, CSS-файл с глобальными дизайн-токенами, небольшой JavaScript для формы и переключения темы, а также исходные прототипы Google Stitch. Панель прогноза пока использует демонстрационные значения; CSV, реальная расчётная логика и backend не подключены.

## 2. Источник требований и место текущей работы в кейсе

Основной документ с требованиями — **Кейс_динамическое_ценообразование_авиабилетов.pdf** (14 страниц). В нём описаны три связанных блока:

1. **Бизнес и аналитика** — математическая модель одного дня полётов, ограничения вместимости, выручка и затраты, оптимальные цены для обычного и пикового дня, смена маршрута, риск снегопада и управленческие выводы. Этот блок занимает страницы 3–9.
2. **Искусственный интеллект** — прогноз спроса на пять направлений из Москвы на период с 1 июня по 1 июля 2026 года. Работа выполняется в Jupyter/Google Colab; результатом служит CSV-файл прогноза. Инструкции находятся на страницах 10–11.
3. **Разработка** — приложение или скрипт, который использует прогноз и показывает ожидаемые продажи при введённых параметрах. Основные требования находятся на страницах 12–14. Это текущая часть проекта.

Блоки связаны: прогноз из блока ИИ можно использовать как вход для разработки. Если собственного прогноза нет, кейс разрешает использовать готовый файл-заглушку **seasonal_forecast.csv**.

## 3. Требования третьего блока: разработка

### Входные данные и назначение приложения

Программа должна принять маршрут, дату вылета и цену билета, найти нужную запись прогноза и вывести:

- количество мест на рейсе;
- сколько пассажиров, вероятнее всего, захотят купить билет;
- сколько билетов можно продать с учётом вместимости самолёта.

В файле прогноза есть пять маршрутов из Москвы на даты с 1 июня по 1 июля 2026 года. Пример кода маршрута в кейсе — MOW-AER. Соответствия кодов аэропортов и городов лежат в **routes.csv**.

### Варианты реализации

| Вариант | Что требуется | Уровень |
| --- | --- | --- |
| A. Скрипт | Принимает пункт отправления, пункт назначения, дату и цену; читает строку из CSV и печатает места и прогноз продаж. | Самый простой |
| B. Веб-страница | Форма принимает те же данные, а расчёт выполняется в браузере на JavaScript или TypeScript. | Средний |
| C. Веб-страница с backend | Страница отправляет данные через JavaScript/TypeScript в скрипт или backend API, который выполняет расчёт. | Самый сложный |

Текущая папка подготовлена как простая веб-заготовка, поэтому вариант B естественно сочетается с имеющимися файлами. Однако вариант реализации формально ещё не выбран. Не считать его утверждённым до отдельного решения.

### Формула простого прогноза

Для введённой цены используется медианный сценарий спроса. Базовый спрос берётся при базовой цене из routes.csv, а чувствительность спроса к цене — из того же файла.

- Желаемый спрос = 0.5_base_demand − price_sensitivity × (введённая цена − base_price)
- Прогноз продаж = min(seats, max(0, желаемый спрос))

Таким образом, продажи не бывают отрицательными и не превышают число мест. Для расчётов нужно использовать исходные числовые значения; форматирование и округление предназначены для отображения.

### Форма данных прогноза

Для каждой пары «маршрут + дата» в CSV есть:

- route — код маршрута;
- date — дата вылета;
- seats — число мест;
- квантили 0.1–0.9; в каждом сценарии указаны:
  - X_base_demand — спрос сценария X при базовой цене;
  - X_price — оптимальная цена для сценария X;
  - X_price_demand — прогноз продаж по этой цене.

В подключённом CSV заголовки содержат `route`, `date`, `seats` и набор квантилей спроса. Форма использует `route` и `date`; остальные поля предназначены для будущей реализации расчёта.

### Дополнительные функции

| Функция | Варианты |
| --- | --- |
| График распределения спроса при введённой цене | A, B или C |
| Регистрация | Только C |
| Авторизация | Только C |
| Размещение на хостинге | B или C |

Для графика спрос по каждому квантилю пересчитывается той же линейной формулой, но вместо медианного спроса используется X_base_demand соответствующего сценария. Между соседними квантилями вероятность составляет 10%. На графике должны быть видны медиана, вместимость самолёта и возможное превышение числа мест. Медиана графика должна совпадать со значением желаемого спроса в простом прогнозе.

Оценка зависит от сложности выбранного варианта, понятности интерфейса, количества реализованных функций и их работоспособности. Для веб-вариантов требуется либо видеодемонстрация локальной работы, либо доступное размещение приложения. Локальное видео не засчитывается как размещение на хостинге. Код сдаётся в ZIP проекта или ссылкой на открытый GitHub-репозиторий; файлы для сдачи должны быть названы ФИО.

## 5. Визуальная концепция из Google Stitch

Прототипы показывают аналитическую панель с названием «Рассчитай спрос». Основной сценарий включает:

1. выбор направления, даты и цены;
2. расчёт прогноза спроса;
3. карточки вместимости, спроса и продаж;
4. предупреждение, если спрос превышает число мест;
5. график распределения спроса и квантильные значения P10–P90;
6. рекомендацию по тарифу.

На мобильных макетах также показана нижняя навигация «Спрос», «Маршруты», «Загрузка», «Риски». Это визуальная идея, а не обязательный список экранов из PDF.

Статические макеты используют пример Москва—Сочи, 15 июня 2026 года, 180 мест, цену 8 500 ₽, медианный спрос 214 и неудовлетворённый спрос около 34 пассажиров. Эти числа являются демонстрационным содержимым макетов и не подтверждены подключённым CSV.

HTML-файлы Stitch — самостоятельные визуальные прототипы. В частности, desktop-примеры содержат CDN Tailwind, внешние Google Fonts, Material Symbols и большую встроенную разметку/конфигурацию. Их следует использовать для понимания внешнего вида и поведения, а не как окончательную архитектуру приложения.

### Расхождения между дизайн-источниками

- Скриншоты _5 и _8 показывают тёмную и светлую версии. При этом HTML _8 помечен классом dark и содержит ту же тёмную конфигурацию Tailwind, что и _5, хотя его скриншот светлый. Для светлой палитры ориентируйся на screen.png, а не на встроенный конфиг _8.
- aero_orbit/DESIGN.md содержит подробную палитру в верхнем YAML-блоке, близкую к тёмной теме _5. В поясняющем тексте ниже указаны иные оттенки, например #0A0A0B, #16181B, #F5A524 и #0F8FAE. Поэтому этот файл не полностью согласован сам с собой и со скриншотами.
- При выборе финального внешнего вида лучше использовать утверждённый скриншот как визуальный ориентир, PDF — как источник функциональных требований, а CSS-токены — как место хранения окончательно согласованных цветов и шрифтов.
